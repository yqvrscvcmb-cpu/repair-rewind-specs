# Repair Rewind — verification status

This page describes the tested scope of the prototype as of 23 October 2026. Independent functional, fresh-import and final-video reviews passed within the bounds described below. The source and demonstration are public; final Devpost submission remains pending. This is not a hardware or human-acceptance certificate.

## Standalone session logic

Ten Node tests passed for the recording/reversal engine. Run `npm test` with Node.js 22.6 or later; no npm dependencies are required. Tests cover recorded order, copied numeric poses, explicit confirmation, invalid-action rejection, pause/resume, undo and reset.

## Native Lens Studio Preview

Native TypeScript compilation succeeded in Lens Studio 5.24.1. Independent review verified the five design criteria against current source, native assertions, correlated mouse input and actual Preview captures.

The final project save and ordinary Ready state were also independently verified: zero recorded/returned parts, 1.6-second motion, debug colliders off and test auto-start off. The final runtime had no observed application JavaScript errors; editor depth-format and SIK batching warnings were retained separately. The Ready screenshot in the README is actual Preview output.

## Fresh source import and final scene

A copy of the corrected project containing exactly the 83 tracked source files imported and compiled without copying the original project's Cache, Support or local configuration. This was a fresh project directory on the existing development host, not a clean-machine or offline-install test. All 83 files in that corrected copy stayed unchanged through its import and tests. The six included package archives regenerated their local source; independent review compared 418 archive-owned TypeScript/JavaScript files with the regenerated bytes.

The initial import exposed two unused, invalid environment-texture references. The official editor API cleared those references and saved the scene; native serialization also renewed the existing LEAF bridge identifiers. All other source files, scripts and provider archives remained unchanged. This clears stale references; it does not restore HDR illumination.

After that correction, the fresh copy passed `repair-rewind-loop` in **27.421 s** and all **10 Node tests**. The original project was reopened, compiled and observed in its ordinary empty Ready state. The seven-scenario table above and the recorded footage retain their earlier provenance; only the core loop and standalone tests were rerun on the final scene.

Included package versions were observed during import. Interact declares Leaf 2.0.0 while the included Leaf descriptor is 2.0.2; this combination passed the bounded checks here, not a universal compatibility test. Depth-format fallback, SIK batching and a LEAF plugin state-save warning remain documented locally.

## Recorded demonstration

The final video is **2:20**, with 4,200 frames at 30 fps, 1080 × 1920 pixels, English narration and captions. Both source takes were recorded with Lens Studio's native Preview Record Video control, using actual mouse input and simulator camera movement. The edit uses selected passages from those takes; idle time is omitted. At the ring-return cut, the preceding sample still says “moving” and the following shot says “confirm placement.” No mockup replaces the native footage.

Independent review checked the final presentation timing, full decode and 21 sampled frames. Captions were legible in those samples, and completion and reset states were coherent. This was technical and sampled visual review, not a human listening test or inspection of every frame. Narration timing was checked against the edit and caption text; subjective audio quality remains unverified.

## Limits

The demonstration uses a simulated cover, retaining ring and gear, with memory inside one Lens session. Physical hand interaction, repair correctness, device comfort and long-term spatial anchors have not been tested. The prototype does not recognize objects or diagnose repairs. A simulated camera move supports only the observed Preview behavior; it does not establish real-world tracking accuracy.
